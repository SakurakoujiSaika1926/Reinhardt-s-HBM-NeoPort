# Legacy ID Policy

The 1.7.10 source is the authoritative reference. Its static field initialization and old Forge lifecycle hooks cannot be copied directly into 1.21.1 without a large rewrite, but its registry names are valuable.

This port keeps old ids by loading generated text lists from:

- `src/main/resources/legacy/reinhardtshbm/items.txt`
- `src/main/resources/legacy/reinhardtshbm/blocks.txt`

`item_catalog.txt` is generated by `tools/rebuild_legacy_item_manifest.ps1` from the direct 1.7.10 `ModItems.java` registrations. `items.txt` is then regenerated by `tools/split_legacy_item_manifest.ps1`; it contains only unresolved, non-retired standalone item ids.

`block_catalog.txt` is generated from the actual 1.7.10 `ModBlocks.java` registrations by `tools/rebuild_legacy_block_manifest.ps1`. `tools/audit_legacy_block_manifest.ps1` compares that source catalog with formal 1.21.1 registrations and `blocks.txt`, writing `block_audit.txt`. The audit is intentionally separate from rewriting `blocks.txt`: a block is removed from the unresolved manifest only after its block, BlockItem, behavior, assets, recipes, and dependencies are actually ported.

`tools/audit_legacy_item_manifest.ps1` writes `item_audit.tsv` for every unresolved standalone item. It records the 1.7.10 initializer class, texture and Chinese localization presence, and whether the same id is a registered legacy block. This is the required migration inventory; it prevents ordinary items, stateful tools, containers, and block items from being conflated.

The ids in `items.txt` are registered through `LegacyHbmContent` as placeholder items. When real behavior is ported, remove that id from the placeholder path by adding it to `CORE_ITEMS`, then register a real class in `HbmItems`. Block ids follow the equivalent `CORE_BLOCKS` path. Base `gun_` items remain in the 1.7.10 catalog for auditability but are deliberately retired from the 1.21.1 registry.

Use the same registry path unless there is a strong compatibility reason not to. For example, old `ingot_uranium` remains `reinhardtshbm:ingot_uranium`.

The namespace changes from legacy `hbm` to `reinhardtshbm` for this project. Cross-mod compatibility aliases can be added later through tags, recipes, or optional remapping logic.
